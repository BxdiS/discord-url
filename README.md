# discord-url

Монитор доступности Discord invite/vanity кодов. Принимает ссылки вида
`discord.com/invite/КОД`, следит за ними и присылает в Telegram уведомление
в тот момент, когда код освобождается.

Vanity-URL (`discord.gg/имя`) выдаётся серверу только на Boost Level 3
(14 бустов). Как только сервер теряет Level 3 или удаляется, код возвращается
в общий пул и достаётся тому, кто успел первым. Руками это не отследить.

## Чего инструмент не делает

Не забирает код автоматически. Установка vanity идёт через
`PATCH /guilds/{guild.id}/vanity-url`, ботам этот эндпоинт недоступен —
автозахват потребовал бы пользовательского токена, то есть selfbot и прямое
нарушение Discord ToS с риском перманентного бана аккаунта.

Вместо этого приходит мгновенный алерт, а код вы забираете сами:
`Настройки сервера → Пользовательская ссылка-приглашение`.

## Установка

```bash
python -m venv .venv && .venv/Scripts/activate && pip install -e .
```

Без установки пакета работает `python run.py <команда>`.

## Настройка

При первом запуске из шаблонов создаются рабочие файлы — `config.toml`,
`.env` и `watchlist.txt`. Все три в git не попадают.

```bash
dcurl init
```

Дальше заполните `.env`:

```
TG_BOT_TOKEN=...   # @BotFather -> /newbot
TG_CHAT_ID=...     # @userinfobot пришлёт ваш ID
```

И `watchlist.txt` — по одной ссылке или коду на строку:

```
discord.gg/example
https://discord.com/invite/another?event=42
somecode
```

Проверить, что уведомления доходят:

```bash
dcurl test-notify
```

## Оптимизация трафика и IP

### Proxy

Если вы отслеживаете много кодов с одного IP, Discord Cloudflare может вас временно заблокировать. Доступны два режима:

#### Режим 1: Port range (диапазон портов)

**Самый экономный режим.** Используется один хост и один логин, но разные порты:

```toml
[proxy]
urls = "user283654o34626r400970:o7y50q@pool.proxys.world:10000-10999"
```

Это создаст 1000 прокси-адресов с портами от 10000 до 10999. Демон будет использовать первый, но у вас есть запас.

**Примеры:**
- `user:pass@proxy.example.com:8000-8099` — 100 адресов
- `user283654o34626r400970:o7y50q@pool.proxys.world:10000-10999` — 1000 адресов

**Альтернативный формат:**
- `pool.proxys.world:10000-10999:user283654o34626r400970:o7y50q`
- `proxy.example.com:8000-8099:user:pass`

#### Режим 2: Full proxy list (разные прокси)

Используйте, если у вас прокси от разных провайдеров или разные IP:

**Из файла:**
```toml
[proxy]
urls = "proxies.txt"
```

Файл может содержать:
```
pool.proxys.world:10000:user1:pass1
pool.proxys.world:10001:user1:pass1
another.proxy.com:8080:user2:pass2
http://direct.example.com:3128
socks5://sock.proxy.com:1080
```

**Или список в конфиге:**
```toml
[proxy]
urls = [
    "http://user:pass@proxy1.example.com:8080",
    "socks5://proxy2.example.com:1080",
]
```

**Конвертер для ваших прокси:**
```bash
python convert_proxies.py "proxys_59057 (3).txt" >> config.toml
```

**Поддерживаемые форматы:**
- `http://user:pass@host:port` — стандартный URL
- `host:port:user:pass` — сервис-формат
- `host:port` — без авторизации
- `socks5://host:port` — SOCKS5 прокси

Демон использует первый прокси из списка для всех запросов.

### Минимизация трафика

Свежие свободные коды — это деньги: если вы код забрали, 12 часов проверять его каждый цикл смысла нет. Используйте `skip_free_hours`:

```toml
[proxy]
skip_free_hours = 12.0
```

Если код освобождается, вы получите один алерт. На следующие 12 часов демон его не проверяет и не тратит трафик. После истечения периода проверка возобновляется.

Поставьте `0`, чтобы проверять свободные коды всегда (по умолчанию).

## Использование

Разовая проверка, без демона:

```bash
dcurl check discord.com/invite/example
```

```
discord.gg/example   занят — Мой сервер, ~1500 участников, vanity, бессрочно
```

Постоянное наблюдение по `watchlist.txt`:

```bash
dcurl watch
```

Наблюдение за конкретными кодами, минуя watchlist:

```bash
dcurl watch discord.gg/one discord.gg/two --interval 30
```

Коды выхода `check`: `0` — все свободны, `1` — есть занятые или неизвестные,
`2` — ошибка ввода или конфига.

## Как это работает

Опрашивается публичный эндпоинт `GET /invites/{code}` — авторизация не нужна.

| Ответ | Трактовка |
|---|---|
| `200` | занят; из тела берутся сервер, число участников, тип и срок истечения |
| `404` + `code: 10006` | свободен |
| `429` | глобальная пауза на `retry_after` и повтор |
| `5xx`, таймаут, обрыв связи | **неизвестно** — никаких выводов и никаких алертов |

Три вещи, на которых держится надёжность:

- **Свободным считается только настоящий `404` от Discord.** Таймаут, `5xx`
  и даже `404` без тела Discord (например, страница ошибки Cloudflare) дают
  статус «неизвестно». Иначе каждый сбой сети будил бы вас ложным алертом.
- **Перед алертом код перепроверяется трижды.** Одиночный `404` может быть
  следствием кратковременного сбоя. Цена — несколько секунд задержки.
- **Темп 1 запрос/сек** при разрешённых Discord 50/сек. В лимит Cloudflare
  (10 000 «невалидных» ответов за 10 минут) считаются только `401`, `403`
  и `429` — `404` туда не входит, поэтому долгий опрос свободных кодов
  безопасен. Опасен только шторм `429`, и на него стоит глобальная пауза.

Если Discord сообщил `expires_at` (у обычных инвайтов он есть, у vanity нет),
демон не опрашивает код всё это время вслепую, а просыпается сразу после
названного срока.

## Файлы

| Файл | Назначение |
|---|---|
| `config.toml` | интервал, темп запросов, число подтверждений |
| `.env` | `TG_BOT_TOKEN`, `TG_CHAT_ID` |
| `watchlist.txt` | отслеживаемые коды |
| `state.json` | последний статус каждого кода; переживает перезапуск, чтобы алерт не повторился |
| `history.jsonl` | журнал переходов: когда, что, как долго держалось |

## Разработка

```bash
pip install -e ".[dev]" && pytest
```

Переменные окружения для отладки:
- `DCURL_HOME` — каталог с конфигами и состоянием
- `DCURL_API_BASE` — подмена базового URL API (удобно гонять демона против локального мока)
- `TG_BOT_TOKEN`, `TG_CHAT_ID` — переопределяют значения из .env
